# 当前 Direct 轨迹纠正入口

Project Decision/Executor 的生产 trace 和 StateTune 准入见 [Project 数据入口](PROJECT_ROLE_DATA_PIPELINE.zh-CN.md)。本页只描述尚被使用的 Direct 离线纠正机制；Direct 候选不得改标签充当 Project 角色训练数据。当前授权、可训练库存和 Agent 指标只看 [交接](HANDOFF.zh-CN.md)。

`scripts/run_trace_correction_pipeline.py` 提供 `prepare`（验证真实来源和完整生成边界、登记输入）、`run`（在事先授权的预算内请求教师/审核并实际验证候选）和 `report`（报告所有候选、失败、拒收及分布）。未提交的批次编排源码和候选工件不构成已发布入口；不得因为返回了作者答案就宣称数据已冻结或 Agent 已改善。

## 输入和准入

- 来源只接受当时实际可见的生产 trace：绑定 run、模型/State、协议、完整输入 token、原始输出、工作区快照、可用动作、保护路径、公开合同与其 SHA。评测用途不能通过改名变成训练来源。
- 原始输出和人工/教师纠正目标分开保存。教师请求需有预先登记的 API 身份、价格、总预算及可恢复账本；超时或结果未知不自动重发，也不把付费生成当作已执行的正例。
- 编辑目标须在隔离副本经公开检查失败→通过；命令目标保存真实退出码与回执，预期失败可以是有效诊断。读取和回答需对应的原始工具证据及独立语义审查；不能仅凭自报通过冻结门。
- 导出与训练加载时重新核对来源、身份、mask、token、切分、近重复、任务族隔离、覆盖和固定回归。拒收必须明确报告，不能补造 token、执行记录或独立审核。
- 项目级得分、变更和终止原因必须独立验证；局部行为通过不等于整题通过。最终保留 Holdout 不参与准备、纠正或本地默认测试。

工程判断原则见 [经验](LESSONS.zh-CN.md)；任何新的付费调用、训练或正式数据版本仍按 `AGENTS.md` 的授权与预登记执行。
