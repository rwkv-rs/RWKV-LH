# 缺陷分组与下一阶段：先把真实失败变成可审核来源

2026-09-14。1万条仍是计划；本轮不生成数据集或训练。完整逐项台账见 [DEFECT_REGISTER](DEFECT_REGISTER.zh-CN.md)。产品目标仍是 RWKV 专属 Harness 与 Code Agent。

## NeoHorse 可以借鉴什么

附件介绍 NeoHorse-1。核对[官方仓库](https://github.com/TokenRhythm/NeoHorse)和[技术报告](https://arxiv.org/abs/2609.08183)：它基于 Qwen3.5，使用路由反馈调整数据课程，并结合 on-policy distillation；这是初步自改进探索，不是 RWKV 或 StateTune 的验证。不能把文章部署指令视为本项目授权，也不直接搬入新路由角色。

对本项目有用的是：从实际执行记录发现缺口，区分轨迹是否完整和结果是否正确，再验证纠正、调整采样。强模型实际接管、给过建议、任务自身难度是不同信息。论文的学生轨迹上教师监督也不等于把强模型最终答案当 RWKV 成功样本。官方首页可见模型说明、examples 与报告，不能据此声称已有可直接复用的完整训练/Harness 实现。

## 可以合并主题，不能抹掉子问题

|主题|覆盖缺陷|如何验证及不可合并之处|
|---|---|---|
|工具协议|M01 非法参数、混用字段|实际 parser/Harness 检查；不与写入内容错误合并，合法调用也可能做错事。|
|有效修改|M03 未接实际入口；M10 按明确方案仍写回原内容|分别检查真实差异、用户入口与行为；有 diff 不代表入口有效，无 diff 也不能一律认错（可能本来已满足目标）。|
|证据与表述|M04 测试失败却说通过；M05 数字及关系失真；M06 需求当实现；M08 无依据补充；M11 写成功就说改好了|可共用来源绑定主题，但保留数字、来源、运行状态、修改状态四类切片。M11 与 M10 必须分别计分：动作失败与虚假报告不是同一问题。|
|纠错与推进|M02 重复读取；M07 不采纳正确纠正或吸收错误建议；M09 无交付/下一步能力待验证|纠正必须核实，合理重读保留；没有获得续跑机会不能说模型用完机会仍失败。M09 尚无充分“错误下一步”证据。M07 可同时标注证据问题，每条来源只计一次样本。|
|摘要覆盖|M08 关键遗漏|与无依据补充单独评分；主要信息与重要限制是目标，一般细节可省略。不能把所有遗漏当幻觉。|

以上是数据主题归并，**不是已经证明共同模型根因**。不能合并独立完成/建议后完成/强模型接管，不能合并原始实验分母，不能用重复改写凑独立来源数量。

## 不进模型纠错标签的问题

- E01：观察排序/重复注入，已有工程回归；损坏输入不能给模型背锅。
- E02：过细的摘要全或无评分，属于验收设计；旧 0/8 保留但不解释成不会总结。
- E03：建议模板偏摘要，是待验证输入假设。
- E04：历史重复计数限制续跑，是策略交互；不能直接归因 RWKV 不听建议。
- E05：依赖集成和共享文件冲突尚未闭合，是工程能力缺口，训练不能替代实现。
- E06（本轮新增）：离线重放器把 coding scope 交给只读 Harness，真实编码来源被拒绝。已最小修复及回归；不是生产读写或 State 丢失的证据。
- R01/R02：读取与已有修改/真实测试成功记录是正向控制，不是缺陷；仍审查旧强制终止等来源限制。

## 已开始的开发与下一步顺序

1. 修复已有 direct_trace_data 重放入口，复用生产输入构造器和真实 State 链，不新建协议。编码 scope 使用实际 ActionHarness，workspace 取记录身份；不执行历史工具，不改原输出。
2. 将能精确重建 token/State 的失败来源送入审核，重建失败隔离。重放成功只证明输入可复核，不等于纠正合格。当前训练准入仍只有已实现的读取/摘要标签；编码纠正准入尚未实现。
3. 下一开发增量是编码纠正验证：基于当时可见输入提出候选，在隔离原工作区执行，检查实际改动与用户入口行为；保留失败候选，禁止未来观察、隐藏验收和接管成果冒充独立输出。先冻结审核规则和红绿回归，再实现准入。
4. 按上述子类审核覆盖、正向例外与来源家族去重，之后才讨论获准的1万条构建。纠正不足时报告缺口，不机械扩写数量。训练与固定任务级验收单独登记，不能预设一个 State 能解决所有类别。
5. 生产侧继续 RWKV 默认执行、有界强模型协助；依赖集成作为独立工程任务，不为训练暂停所有并发/协作工作。
