# 架构、RWKV行为与待验证假设

## 2026-09-21：状态驱动的续写与任务闭环

Owner 明确要求以 RWKV 是状态驱动的续写模型为设计前提，并允许借助强模型。完整审查、历史对照、严重问题与建议链路见 [ARCHITECTURE_REVIEW_R1_20260921](../data/experiments/ARCHITECTURE_REVIEW_R1_20260921/REPORT.zh-CN.md)。这是设计审查，不代表新架构已经接线，也不恢复暂停中的训练、生成或评测。

后续实现必须保持以下原则：

1. 程序继续调用 generate 不等于模型收到明确任务。每次决策都要有当前局部目标、阶段、真实反馈、未完成计划、可选决策和明确续写边界。
2. 训练初始 State、任务中的 Native State、持久计划/事实记录分别管理。State 传递正确不证明目标保持和推理正确；显式任务记录也不替模型作业务判断。
3. 同一语义工作单元保留连续 State；独立子任务可以新建 State，必须显式携带依赖证据和约束。不能按每个工具动作重置，也不能静默截断未完成计划。
4. RWKV 局部计划必须进入执行反馈闭环，支持动作、计划更新、求助、子任务报告和最终完成候选。简短进度判断可以与下一动作同次生成，不强制冗长思维输出或逐步多模型审核。
5. 强模型可在复杂项目开始、困难/矛盾和集成边界规划、诊断、综合，必要时接管。RWKV 保留工具选择与局部执行能力；建议和计划不是已执行证据，接管成果如实归属。
6. 合法工具调用、工具成功、模型提交、目标完成及外部验收是不同状态；结束必须对应目标覆盖和真实证据，预算耗尽只能中断。
7. 输入协议、工具结果投影、stop 边界、State 续接、生产采集和训练构造必须一致。历史中“观察后重述目标”的失败对照要保留，不能把补一句提醒当作已证实修复。

本轮确认：当前 CLI/Web 直接入口没有启用旧 Planner 链；advice 提示明确禁止 plan；R38 首次生成含计划/代码但协议不符且截断；读循环之外还有重复写入和重复失败命令。取消异常传播有离线复现。完整工程回归 1991 passed / 0 skipped，不能代替这些架构缺口和真实模型能力验证。

## 2026-09-14 历史诊断

产品入口及职责以ARCHITECTURE为准；本文只记录证据分类，不另建一套架构。

|分类|证据支持的判断|处理方向|
|---|---|---|
|架构缺口|此前显式协助依赖调用方另行启动，无法只提交目标后完成有界转接|本轮实现opt-in终止状态转接；RWKV优先，不读隐藏验收，不逐步审批|
|架构缺口|独立副本已有，但共享文件冲突、依赖集成和最终项目验收未闭合|后续显式依赖与集成任务，不默认自动合并|
|已修工程问题|新协助接口曾把建议放在未消费工具观察前，接管有重复观察风险|前轮红绿修复并核验真实State；不能把修复前行为当模型缺陷|
|任务适配问题|复杂修复每次虽输出一个工具动作，却仍由RWKV承担整个目标的后续规划|按owner经验优先对照语义上原子化的小任务，不能仅靠“一调用一工具”认定已原子化|
|交互待验证|建议有摘要审核措辞；继承历史重复计数导致建议后1/2调用即中断|分别测任务建议语义与重复保护，不混合改动，不无限续跑|
|RWKV可观察行为|材料、State、正确根因建议均可见时仍读取、不修改、不测试|保留真实轨迹；是当前配置的执行表现，不等于已定位模型内部原因|
|RWKV可观察行为|存在非法参数、数字/来源混淆、将建议测试当运行的历史样本|固定任务忠实性验收；工程回归不能代替模型能力验证|
|未知|输入负担、排列顺序、State数值质量、知识及目标保持分别造成多少损失|一次变一个因素做对照；目前不能称为已证明根因|

原子化的下一轮方向：简单任务直接交RWKV；RWKV可在完成当前小任务后报告真实结果并提出下一步；建议与已执行事实分开记录。复杂依赖或持续停滞时才由强模型协助分解和综合，RWKV自行选工具和参数完成执行。独立小任务可以并发；有依赖的按真实结果衔接，强模型负责必要分解/综合而非逐步审批。任务数量由目标决定，不能用固定角色流水线或Harness替模型填答案来获得虚假提升。

本轮RWKV完整目标基线与之后的原子化对照分别冻结，不中途把直接执行组改成拆分组。重点指标是最终交付质量、RWKV实际执行占比、全部失败/建议/接管成本及延迟；不是把总调用次数拉满，也不是让强模型完成后给RWKV记功。
