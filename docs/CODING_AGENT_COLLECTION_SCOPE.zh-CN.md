# 面向真实 Coding Agent 的采集范围

owner 最新明确：采集的用途是为 RWKV Coding Agent 准备 StateTune 材料。执行管线的工程冒烟与正式任务库存必须区分。两道历史公开检查只验证接线，不作为正式库存的任务分布样板。

## 正式任务来源与范围

优先从 UltraData-SFT-Agent 的 Code-Agent 任务和项目真实任务复建环境，目标是完成具体仓库工作。Code-Agent 的静态对话须映射到真实初始源码/依赖/测试；缺少仓库版本时标记待复建，不能从参考补丁或未来工具输出反造初始代码。

| 任务方向 | 交付目标 | 必须具备的验收依据 |
|---|---|---|
| 修复 bug | 改正有证据的错误行为，保持相关功能 | 初始错误可复现、期望行为明确、独立回归与原测试 |
| 实现需求 | 将用户要求接入真实入口或调用链 | 可执行的行为检查，不能仅检查新增了函数/文件 |
| 测试反馈修复 | 读取真实失败反馈并完成必要修改 | 原始测试、实际失败/后续结果、未篡改验收依据 |
| 仓库理解与定位 | 解释真实代码行为、限制、调用关系，为编程目标提供依据 | 源码锚点、实现与需求的区分、可核对的数值和入口关系 |
| 验证与交付说明 | 实际检查变更，忠实描述执行与结果 | 本次工具记录、原始输出、最终产物；提交答案不等于测试通过 |

前三类是主要来源目标；后两类用于补足编码闭环能力，不靠大量简单读取/复述挤占库存。具体配额在可复建来源盘点后登记，不先编造比例。

RL Code 仅作可验证实现任务的补充，不把算法题准确率代表仓库编程能力。长文材料只在真实代码库理解/需求分析等编程语境中纳入；通用知识问答、无关摘要及单纯复制参考回答不用于凑 3 万条。来源不足时如实报告，保留质量要求和独立任务计数。

## 任务与单步训练材料的关系

公开版本重新实例化与原环境恢复分开登记：可保留来源中的业务描述，人工登记文本范围和环境适配，绑定真实公开 commit、初始错误、依赖与验收；不从未来补丁倒造源码。原预置测试缺失必须明确披露，不能伪称完全重放。R6 AnyIO 已完成一次此类试采，仍须跨源家族去重后才计正式库存，示例位于 `data/experiments/RWKV_ANYIO_RECONSTRUCTION_R6_20260915/`。

采集单位是一个真实目标下的完整执行尝试。RWKV 自主定位、读取、选择修改、运行验证和修复；任务不必经过固定阶段，也不强制每次调用工具或固定次数。简单工作仍可一次完成。

训练候选之后才从这些完整 trace 的真实调用边界抽取：当时输入/State/可见观察 → 经验证的正确下一步。一次任务可产生多个候选边界，但仍只计一个来源任务。后续强模型纠正只修当时错误，不注入未来测试结果或隐藏答案；本轮先采集，不启动纠正和训练。

## 正式入队清单的审核门

每个任务必须登记：原题身份及修订、原始目标、环境复建来源与初始 SHA、依赖/工具可用性、任务方向、交付物、事前验收约定及适用范围、原始测试/受保护内容、时间与调用预算、任务家族及训练排除关系。

这些是外部采集清单的审查材料，不是模型的步骤表。机器层管线只验证冻结、隔离与资源/协议条件，不根据文件后缀猜业务类型，也不替模型给出修法。

验收先看真实交付是否满足用户目标，不限定正确实现路径。代码产物、测试证据、最终说明忠实性分开记录；“改测试让它通过”、没有接入口、把计划说成实现等必须能被独立检查识别。主旨/限制允许不同措辞，不能以逐字参考答案匹配替代目标验收。

## 下一阶段可复核交付

先交付 SFT Code-Agent/项目来源的环境可复建库存及缺项，再冻结一批覆盖真实编码目标的任务，通过新管线运行。检查实际输入与纠正快照、真实产物及验收，再测并发并扩展到目标规模。

不以静态轨迹条数、生成调用数或重复执行冒充独立任务数；不因管线测试通过就宣称 3 万真实编程题已经准备完成。磁盘自动管理按 owner 当前要求暂缓，约三小时通过 --status 与服务器存储检查查看运行状态。
