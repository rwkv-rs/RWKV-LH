# 当前产品架构与下一阶段

更新：2026-09-14。本文件是当前架构与入口职责的唯一导航；实验分数及详细证据见 HANDOFF 和对应实验报告，不在多份设计中重复维护。产品目标是为 RWKV 构建专属 Harness 和 Code Agent。同质量下的成本、交付时间、吞吐是优化指标，不是已兑现能力。

## 当前一条执行链

用户完整任务 → RWKV 自主选择工具与参数 → Harness 执行 → 原始观察及连续 State → RWKV 继续 → 原始回答/修改副本 → 外部验收。

|职责|实现与边界|
|---|---|
|RWKV执行|`model.py`、`model_session.py`；`model_io.py`唯一输入构造/渲染，不由调度器代选动作或改答案|
|直接执行控制|`read_only_agent._run_job`与`LongHorizonController`直接模式；预算、协议拒绝、工具结果和终止因果记录|
|工具与隔离|`harness.py`；`coding_agent.py`复制工作区并保存每次调用前后快照；只读权限限制由`ReadOnlyHarness`执行|
|独立任务调度|`agent_batch.run_agent_jobs`；全批预检查、spawn进程、独立任务状态和输出、按输入顺序返回原结果|
|按需强模型|`assisted_agent.py`显式建议/接管，`summary_advice.py`构造建议，`strong_session.py`保存原始提供方请求/响应；默认不介入，可显式开启有界停滞接管|
|外部验收|`task_review.py`；按用户目标和真实交付审核，隐藏标准不进入模型；submitted不等于合格|

### 入口

- 推荐批量CLI：`scripts/run_rwkv_agent.py`，同批可包含files/inspect/coding独立任务。
- 单任务修改：`scripts/run_rwkv_coding_agent.py`；原只读批量CLI继续支持并委托同一调度器。
- 现有前端worker调用相同单任务执行函数，本轮不改页面、不做可视化。
- 已删除旧多角色启动CLI及其启动测试、runtime stack的worker启动选项、两份竞争架构文档。`product_runtime.py`等仍被研究回归引用的内部模块保留；本轮未修改owner正在编辑的共享控制器和模型。

这是当前产品路由的统一，不宣称历史代码已全部清理。旧协议并未在本轮升级，不能绕过原版本/输入一致性约束。

## State、失败与协助

连续任务只消费真实观察并续接原State；独立新任务各自zero。调度器不拆任务、不拼接或共享State。预算耗尽、中断、基础设施失败单列，不强制成功回答；当前Goal直接模式不再因幂等无变化写入强制Final；读重复与资源预算仍可中断，不能把中断视为自然完成。旧研究模式的边界仍保留，不能混作直接Agent能力。

简单任务直接交RWKV。困难任务的strong建议、用户目标调整、strong接管分别记录；strong不成为每一步审核关卡。建议不是工具证据，接管成果不是RWKV独立能力；改变目标属于新合同，不悄悄重用旧验收。显式开启on_stall=takeover时，goal_delivery只对已有无交付预算停滞原因做一次有界转接；普通任务不自动调用强模型。没有基于隐藏评分的自动求助。

## 下一大阶段：独立任务交付与协作

已开始实现独立任务的批量接收、读取/检查/修改统一调度和结果交付。任务独立性由调用方根据目标、依赖和写入关系声明，不由路径相似度或模型外的业务分类器猜测。

同一源可被多个修改任务复制，但输出必须互不重叠，且不能与任一输入重叠；各副本不会自动合入源目录。存在依赖的coding任务可显式声明depends_on，按依赖就绪调度；相同基线的不冲突文件变化可保守集成，冲突拒绝并交还调用方。外部最终验收仍独立，尚无自动语义冲突解决。外部进程对源目录的并行修改不在当前快照保证内。

顺序推进：统一独立任务入口及真实小批验证 → 显式strong建议/接管产品接口（本轮实现） → 有依赖任务的集成与验收。每项增加明确能力，不再以每个小错误启动一轮训练。并发效果必须同任务同质量测量；调度器工作不等于模型质量提升或吞吐收益。

## 保留、修改和暂缓

- 保留生产唯一协议、native State、真实工具、只读/修改执行、外部审核、完整trace。
- 合并重复的批量调度；文档只从本页进入，HANDOFF保存状态，两份重复旧设计从工作树删除，依据从Git历史查询。
- 不保留已否定的恢复句/精简菜单为生产分支；停止这两项局部实验。
- 暂缓旧多角色内部模块的物理删除、共享写入自动合并、前端续跑、语义自动求助和训练。逐项以依赖与回归证据处理，不能声称已实现。

## 数据与质量

读取已在固定用例通过；多步修复仍可能重复读取、不执行测试或无交付。这是产品能力限制，不用工程回归掩盖。

trace → 错误归因 → 经验证纠正 → 获准数据版本 → StateTune → 固定回归和任务验收仍是离线通道；当前不训练、不建新dataset。保留模型/State身份、输入输出token、工具观察、父链、协助归属与失败成本。完整逻辑输入token不等于native增量计算或费用；不能仅凭调用减少宣称合格项目成本下降。

## 显式协助的执行约束

统一JSON任务可用`assistance: advice`或`takeover`，从已有`parent_run`继承原目标、工具权限及记录；不允许同时替换目标。父运行不改写，新的输出必须独立。修改父任务使用其交付副本；已观察只读文件或交付清单改变则拒绝继续。任务副本在WSL独立mount namespace中映射到原目标路径，避免为了改路径重写历史State；这不是完整主机安全沙箱。

建议由强模型读取原目标、原回答和真实工具观察生成一次，明确标为非执行证据；RWKV沿原State继续自主选择。尚未消费的真实工具观察先注入，再注入建议。接管创建强模型的全新文本根，通过同一生产输入构造函数投影历史执行记录，不传递RWKV原生张量；投影过的观察只登记一次。建议失败、预算耗尽或非法响应如实终止，不替模型补参数或填写答案。

归属分别为`rwkv_independent`、`strong_advised`、`strong_takeover`；错误任务也记录尝试的协助方式，不意味着完成。原始回答仍须外部验收。保存父trace、父快照、介入事件、新trace、State父链及提供方原始信封；强模型token以提供方usage记录，不能伪称有逐token ID。建议调用、排队及复制时间另计入总耗时，不把执行计时器当端到端时间。

## 当前任务交付与归因

`goal_delivery.py`在共享执行入口外记录总调用上限、剩余时间、原RWKV运行和一次可选接管。它不规划业务、不判定答案合格；完整接口与预算边界见AGENT_BATCH。架构缺口、已观察模型行为和未知原因分开记录在[归因说明](ARCHITECTURE_DIAGNOSIS.zh-CN.md)。后续优先验证语义原子化，以及RWKV“完成当前小任务并提出下一步”的方式；不把一次工具调用等同于已经解决任务粒度问题。

当前工程整改与支持边界见[报告](../data/experiments/RWKV_ENGINEERING_FIXES_R1_20260914/REPORT.zh-CN.md)。强制终止、审计配对、准备预算、worker清理、异常结果与旧只读建议观察顺序已增加回归；不据工程测试宣称模型能力提升。
