# Project 当前预算与输入输出合同

G1K 部署显式配置服务、基座、Decision 和 Executor 的 `max_model_len=25600`。客户端在分配 Native State 前要求服务声明正整数容量，且不小于客户端配置；G1K 部署验收另核对实际服务为25600。通用 RuntimeSettings 的其他模型默认值不代表 G1K 部署容量。

|计划阶段／任务数|无固定数量上限|不截断义务；实际资源耗尽如实中断|

Planner计数使用本地 tokenizer 估算实际发送的请求体，包括当前 mode 的工具、system 和 user 内容；它不是提供方 tokenizer 或隐藏 chat 模板的精确容量，也不保证是提供方计数的上界。提供方实际usage单独保留，不能把32 token安全余量理解为已覆盖任意tokenizer差异。宿主完整审计checkpoint的token数另记为`audit_transcript_tokens`，不再作为第二道模型输入预算门。

项目总调用预算按预留扣减，不等于实际模型生成或工具执行次数。输入检查、快照或传输准备阶段中断，可能已有预留但没有生成开始；原始返回也可能尚未发布到账本。预算预留、客户端开始、实际返回、已发布结果及服务端独有完成结果必须分别核对；未知用量不能补为0，pending不能因存在RESULT文件便视作已解决。

预算候选按单变量、固定题面、RWKV采样seed、检查、总调用和时间对照；源码不得在两臂之间变化。强Planner未因RWKV的seed而获得确定性，仍须用重复基线估计噪声。只有完整功能与Agent完成证据可支持推广，减少截断或提高角色合法率不能替代它。当前实际运行结果与是否保留候选只见[HANDOFF](HANDOFF.zh-CN.md)。

## 输出额度与有效长度

25600是当前G1K的容量配置，不是单次输出的推荐长度。Native把`max_tokens`作为生成停止上限传给采样器，不把该参数改写进角色提示。额度、实际自然结束长度和内容质量分别登记；不能把降低额度当作要求模型自动精简，也不能把放大额度当作已修复重复或错误动作。

长度分布按角色及工具类型拆开。运行命令的短参数、写文件的完整代码、Decision委派理由与最终报告不能共用一个经验分位数。自然结束样本不包含被截断的尾部，失败轨迹又可能重复产生短命令；其P95只描述已观察输出，不是最优预算或功能成功保证。完整JSON、当前角色合法、工具执行成功和完整任务通过是不同层次。

工具由RWKV在本次生成中选择，按工具类型分组是事后分析，不代表运行前已知下一工具。当前运行时仍采用角色额度；分组结果本身不构成新增预算路由器、提前强制工具选择或额外模型调用的依据。

额度筛选先用当前生产边界，固定完整输入、父State、采样参数和decoder，仅改变输出上限，并重复基线检查稳定性。候选生成不执行工具，所得结果只能解释停止和截断机制；推广候选额度仍须固定完整任务、总调用及时间预算的功能对照。重建长历史State不等于扩大配置窗口，也不证明长期记忆质量。表达要求、采样惩罚和训练属于其他实验因素，不在额度对照中同时改动。

## 采样参数与复读

当前对照基线为`temperature=0.1`、`top_p=1`、`top_k=0`、`frequency_penalty=0`、`presence_penalty=0`、`penalty_decay=0.996`，约束解码保持开启。调整采样不改变25600容量配置或1800／4096输出上限；完整JSON也不保证引用合法、内容正确或任务完成。

当前冻结engine使用Native sampler，`VLLM_USE_RAPID_SAMPLER=0`。频率惩罚按本次生成中输出token的出现次数减去相应logit，presence惩罚按是否出现减去相应logit；它们不理解代码语义，可能扰动正常标识符、证据ID与文件内容。默认`penalty_decay=0.996`保留在请求中；本Native路径不执行Rapid的衰减逻辑，非默认衰减配置会被拒绝，不能声称本轮已测试衰减调优。

采样筛选使用相同完整输入、同父State、相同输出上限与当前角色校验，并纳入正常输出对照和重复基线。自然结束、角色合法、精确token重复率、动作改变和完整功能分别报告。精确重复窗口会漏掉不断变化的序号等变体复读；较短输出也可能只是改为继续读取。候选必须检查正常样例退化，且回到完整任务验证。`temperature=0`为贪心，换seed不构成独立随机重复；强Planner仍可能产生不同输入。当前实测和候选是否通过只见[HANDOFF](HANDOFF.zh-CN.md)，不根据单步结果自动修改默认参数。

采样优化只调整 Decision／Executor，Planner 保持原配置；候选须同时保留正常动作和完整任务对照。具体已运行结果、拒绝候选及下一步只在[当前交接](HANDOFF.zh-CN.md)维护。

## 角色联动

Decision 与 Executor 使用独立 lane 和 State，通过账本中的工作合同、实际工具回执及明确声明交接，不相互复制 WKV 张量。Executor 在兼容委派内持续工作，合同不兼容时新建 State。强 Planner 按需规划、诊断或编写检查，独立审查使用不同 lane；最终报告由 Executor 编写，Decision 判断覆盖，Controller 原文返回。

完整执行顺序、逐步事实、检查和完成门统一见[架构](ARCHITECTURE.zh-CN.md)，本文只维护额度及其计量口径。
