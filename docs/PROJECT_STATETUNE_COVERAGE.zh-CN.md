# Project StateTune 覆盖与准入

Decision 学习在明确边界选方向和引用已有对象；Executor 学习在局部合同下选择工具及原样参数。两角色使用独立数据与 State，不能用一个角色的高分代替 Agent 完成。当前训练准入 0；旧数据、生成课程和单样本试点均不复用。

Decision 来源应覆盖真实发生的任务起点、执行让出、局部进展、工具失败、提交、验证返回、目标接受、后继任务委派与最终交付。每条输入只含当时已知事实；后继回执仅用于离线审查，不能倒灌至早先边界。重试、重复 epoch、换路径和同源变种均不增加独立任务数。Executor 来源必须绑定实际工具执行和结果；单纯写出理想命令不是成功执行证据。

每个候选都要报告独立任务/项目数、边界类型与方向分布、有效标签、路径和布局分布、近重复簇、跨切分泄漏、上下文长度及被拒原因。同一任务族、重试或派生副本应留在同一切分；每角色固定一份不变的开发/确认回归。不能为了凑配额编造情景、裁掉必需状态或静默截断历史。真实缺口通过继续采集生产任务补足。

训练前逐行核对当前协议和输入构造、完整 Native token、模型与 tokenizer/State 身份、独立语义审查、有效来源、目标 mask 和固定切分。State 训练保持 fp32io16，目标学习率为 1e-6；每次运行必须预登记优化器、资源预算、初始/输出 State 及 Agent 级验收。角色 CE 或格式 100% 不是保留组合的充分条件。
