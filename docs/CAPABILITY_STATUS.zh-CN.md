# 当前能力与使用边界

目标是RWKV专属Harness与Code Agent；以下是固定开发诊断的证据，不是一般项目成功保证。当前使用zero State，上一轮训练候选NO_KEEP。失败、未完成和强制结束单列，能力阶段不与训练轮次绑定。

| 能力 | 现在的证据与用途 | 限制 |
|---|---|---|
| 明确路径读取短文件 | 固定读取主组21/21，独立补充组3/3；可读取原文、保留来源 | 固定组稳定，不代表任意编码、大小与路径都已验证 |
| 文档摘要、问题回答 | 可以读取并生成有用答案；整改验收后的某摘要固定组zero8/8 | 数字关系、来源归属和关键限制仍有真实错误；不同实验不合并为收益 |
| 代码阅读与缺陷检查 | 能指出部分缺失功能、解释局部实现，已有只读入口 | 会把文档需求说成已实现，或增加无依据结论，需要复核 |
| 运行指定测试并报告 | 现有通过/失败脚本各两遍：实际执行4/4、通过/失败判断4/4；完整任务2/4 | 两次失败报告添加无依据的错误根因；另外两次有夹具位置措辞小误差。提交、执行成功与报告合格分开 |
| 自主定位文件 | 有目录、搜索、读取能力；恢复基线任务1/8合格 | 查询重复、参数错误、预算/提前终止；不适合承诺全仓库独立调查 |
| 明确文件的小改动 | 单处修改阶段最终文件行为7/8，完整任务6/8，另1部分/1不合格 | 2次合格交付受到旧强制结束边界影响；会新增helper却不接入入口 |
| 修改后测试反馈与修复 | 两题各两遍：任务2/4合格、1部分、1不合格；文件3/4，真实执行测试4/4 | 一次实际修复后测试通过；另一次未修改且测试失败，却编造修改后通过。不能承诺稳定自修复 |
| 小范围联动修改、多文件项目 | 新编程入口已实现；CLI/查询函数联动固定组0/2，1无交付、1错误补丁且无回答 | 会重复读取、错误cwd后不恢复、漏接CLI并破坏默认行为；尚不能可靠交付整项目 |
| 强模型建议与接管 | 预算整改后同父State独立0/2、原建议后0/2；显式strong接管0/1合格、1部分满足 | 接管真实修改2文件并运行测试，但默认查询仍失败；2请求预算终止，无回答。来源与费用单列，不计RWKV独立完成 |
| 并发调度 | 前轮完整只读任务串行2/4、并发2为1/4；本轮较难bug检查两臂均0/4 | 本轮实验外层错误使用系统时钟，时延/能耗比较无效；前轮使用单调时钟且包含关系正常，但仍未证明同质量收益；共享修改另验 |

适合当前试用的工作：给明确文件与边界清楚的问题，提取信息、解释局部行为、提出可验证的缺陷假设；或在隔离工作区做明确的小改动，再由独立验收检查。涉及事实数字、接口是否实现、测试是否运行时，必须对照原文或工具记录。

文档问答/只读检查的现有入口是 `scripts/run_rwkv_read_only_agent.py`，参数说明见[只读Agent入口](READ_ONLY_AGENT.zh-CN.md)。小改动及测试反馈新增 [编程入口](CODING_AGENT.zh-CN.md)，复制工作区后使用同一生产执行链；入口可用性与模型任务成功率分别验证。原文材料和trace保留，程序不代填业务参数或答案。
