# Planner 步数限制整改

日期：2026-09-07；轮次 `PLANNER_UNBOUNDED_PLAN_R1_20260907`。

本轮未运行 Agent，无新增 Strict / completed / mutation / 终止原因指标。此前 R2 A 仍为 Strict 0/12、completed 0/12、mutation 0、12 次 `strong_planner_unavailable`；B 未运行。本轮是 owner 授权的计划规模规则修改，不是 StateTune 训练轮次，也不重评分原始诊断输出或旧两臂结果。

## 授权与根因

owner 明确要求：“这个五步的要求去除掉，对于planner来说就不应该存在步数的要求”，并指出这种限制与让 RWKV 仔细选择结束存在冲突。

此前五步规则不是“第五步直接完成”的成功条件，而是人为限制计划范围：提示词要求 Planner 只发下一到五步；schema 限制步骤、阶段和依赖数量；`GoalPlanPatch` 限制一次增加与替换之和；`RollingGoalPlan` 限制累计未完成步骤；`GoalStageReviewRequest` 又限制一次已完成阶段的步骤数。只删除提示词不能解除下游拦截。较长计划会被拒绝并触发无必要的修复或续规划调用，改变 RWKV 可见计划范围。

修改前证据为 `RED_TESTS.log`：11 个相关测试失败，其中包含补丁数量、累计开放计划、阶段检查和提示词/schema。源代码基点在本地提交 `606b0ddc`；该提交只新增先前连接诊断工件，生产源与诊断时一致。原始 13.3B 输出报告位于相邻 `LOCAL_13B_SUPERVISOR_CONNECTION_R1_20260907/`，不能把该输出改造成回归测试预期来掩盖模型字段错误。

## 实施

- Planner 提示词改为按任务需要规划，删除五步、总步数硬门、只补一个后续阶段等措辞。
- Goal Planner schema 删除新增/替换阶段、阶段内步骤、丢弃步骤 ID 与依赖数量上限，以及阶段编号的任意最大值。
- 删除补丁总步骤、累计未完成步骤和阶段检查输入的五步运行时拦截。
- 阶段正整数、非空阶段、有效字段和 phase、唯一 ID、合法依赖、阶段内独立、根路径不冲突、目标义务绑定、不可改写完成步骤等合同继续生效。
- 更新 README、HANDOFF、统一规范和 AGENTS，记录任务所需规模与证据驱动的结束判断。

没有修改模型、State、JSON transport/decoder、Planner 输出 token 配置或其他角色职责。阶段检查入口同步移除数量拦截，是接收完整合法计划所必需的下游一致性修改，不增加角色或改变检查职责。每步证据条目、根定位、义务绑定数量及历史事实投影的既有边界是独立内容/资源约束，本轮没有扩大这些范围。

## 验证与结束条件

新增回归覆盖 6/19/64 步计划的共享序列化与解析、全部步骤和阶段投影、在既有未完成计划上续加、多步骤替换和丢弃、阶段检查输入、超过五个依赖的 fan-in，以及错误依赖/同阶段依赖/根冲突的原子回滚。19 步逐步审计回归确认越过旧五步边界不会完成，仍有未完成步骤时不得把计划标完成。

真实 Controller、Store 重载及较长阶段的检查回归记录与完整测试结果在本目录保存。测试使用生产 dataclass/builder 构造输入，保留私有验收隔离；不读 Holdout，不调用模型，不以单元回归声称 Agent 增益。

结束路径审计见 `TERMINATION_AUDIT.zh-CN.md`：当前 Goal Loop 没有达到某个步骤/阶段/动作数量即写入 completed 的分支；计划仍须满足未完成步骤清零及目标义务阶段证据覆盖，再经过 RWKV Finalizer/Final Auditor 的既有完成校验。执行资源预算导致中断或阻塞，不作为成功完成。未修改这些门。

## 全局影响与实际限制

影响范围是当前 Goal Planner 的新计划、修复、续规划、持久化重建和阶段边界，适用于所有任务，不含题目路径或后缀特判。已经完成的步骤不允许修改，旧冻结结果不重算。

取消数量上限不代表模型上下文无限。较长计划仍可能触发上下文、输出 token 或执行资源预算，这些需要在新运行前独立冻结。当前 Planner 生产输出预算仍为 1,800 tokens，13.3B 的单次诊断完整 JSON 后缀已超过该预算，因此尚不能宣布本地后端接入完成。Stage Checker 仍只获取有界的近期 action facts；完整步骤和 accepted evidence refs 的传递不能等同于传递每个原始 Action 的全部内容。本轮不改变这项角色上下文设计。

13.3B 已知 JSON mode 缺依赖、思考前缀边界以及原始计划字段/依赖错误仍待接入处理。19 步本身不再是新合同缺陷，不能据此忽略其余错误。后续模型测试必须另建冻结并完整运行新的双零两臂，不能把变更后的结果与旧中转 R2 A 拼接比较。
