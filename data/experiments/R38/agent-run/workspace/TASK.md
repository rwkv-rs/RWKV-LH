# 构建完整的个人日程管理系统

从本目录的空项目开始实现一个真实可运行的单用户 Web 应用，不只写计划、静态演示或单文件补丁。
使用 Python 标准库 HTTP 服务和 SQLite，前端使用原生 HTML/CSS/JavaScript，无需外网、npm 或 pip 安装。至少将后端、HTML、JavaScript 分成独立文件，附 README 和可运行的自动测试。

启动约定：`python3 app.py --host 127.0.0.1 --port 8080 --db /tmp/calendar.sqlite3`。端口和数据库路径均须接受参数。首次自动建表；不同数据库彼此隔离。浏览器访问 `/`，API JSON 不返回 HTML。所有文字可安全呈现，不能将日程标题作为 HTML 执行。

功能：日历分类（名称/颜色）、日程新增/编辑/删除、全天日程、月/周/日/列表视图、按日期范围/日历/关键字筛选、冲突提示、每周重复日程、刷新及重启持久化。页面应可正常操作，布局清楚，有错误和空状态提示。

公开 HTTP 接口约定：
- GET /api/health -> 200 {"ok":true}
- GET /api/calendars -> JSON 数组；POST /api/calendars 接收 {"name":"工作","color":"#2563eb"}，返回 201 和含 id/name/color 的对象。
- GET /api/events -> JSON 数组，按开始时间升序。可选参数 start、end、calendar_id、q。日期区间使用 [start,end)，返回与区间相交的日程；q 在标题、描述、地点中作不区分大小写的子串搜索。calendar_id 过滤日历。
- POST /api/events 接收 calendar_id、title、start、end，以及可选 description/location/all_day（默认空字符串/false）。开始和结束必须是带时区的 ISO 8601 字符串；保存真实时间含义，必须 end>start。返回 201 和包含 id 及这些字段的日程对象。
- GET /api/events/{id} 返回对象；PUT /api/events/{id} 接收与创建相同的完整日程字段并返回更新后的对象；DELETE /api/events/{id} 返回 200 或 204。不存在的日程返回 404。
- 空白标题、非法日期、无时区日期、end<=start、不存在的日历、repeat_weekly 超出整数 0..12，均返回 400，不写入部分数据。
- 同一个日历的时间相交日程返回 409，首尾相接不算冲突，不同日历不相互阻挡。编辑时排除自身。
- repeat_weekly 可选，默认 0；正数 N 表示在初始日程之后再创建 N 个相隔七天的日程。重复创建成功返回 201 {"events":[初始日程,...]}。任一实例冲突必须整体回滚，不得只写一部分。

浏览器交互约定（让用户和自动化都能访问）：
- 有“新建日程”按钮，点击后显示带可访问标签的表单：“标题”、“开始时间”、“结束时间”、“日历”。时间使用 datetime-local 输入；日历为 select；有“保存”按钮。
- 有可见搜索框，标签“搜索”；有“月”、“周”、“日”、“列表”四个按钮，可以切换实际日期呈现，不能仅改标题。
- 有标签“日期”的 date 输入，可以跳转显示指定日期的日程。默认显示今天。列表和日期视图呈现实际日程标题；点击日程可编辑、删除。
- 浏览器表单的本地时间转换为带时区的 API 时间；错误必须显示，不能在失败后假称保存成功。
