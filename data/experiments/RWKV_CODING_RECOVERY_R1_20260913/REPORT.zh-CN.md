任务级：有效无建议组 0/2（两次无交付）；有效建议组 0/2（一次无交付、一次无效补丁且无回答）。completed/新答案提交 0，实际 mutation 1，虚假完成 0；四次都以 identical_failure_budget_exhausted 中断。不是项目 Strict。另保留四次初始化失败的基础设施无效记录，新 RWKV 生成 0；不并入有效通过率。

## 本轮工程交付

`read_only_agent.py` 的共享入口新增 termination_reason、termination_evidence 和 command_executions。现在分别显示 Controller transition 边界、模型 generation 上限、墙钟上限、同类失败边界和执行异常。异常优先记录，续接仅查本次新增因果事件，不误用父任务终止记录。保持原 termination 粗分类，预算不算完成，原始答案不改写。

命令退出码为 1，即使符合模型声明的 expected_exit_code、工具 success=true，仍按真实非零退出码报告；FileNotFoundError 与无退出码的启动失败单列。exited 只表示有命令退出码，不自动证明测试脚本运行或通过；其他无确定退出证据的情况标 unconfirmed。续接的完整 actions/command_executions 保留父历史，本轮 ACCOUNTING 与正式审核只计新增部分。

同一共享循环增加受控 State 准备和观察注入接口，用于本轮隔离诊断。目标 workspace_root 属于不可变 Goal digest，不能直接改路径。实际采用 Linux 私有挂载命名空间：各副本在子进程中绑定到原路径，保留原 Goal/State；宿主原工作区和父 State 文件逐 SHA 保持。挂载写隔离预检通过，真实运行也逐次核验宿主源不变。这个诊断编排还不是公共 CLI 的通用续修功能。

一次建议复用 summary_advice 的唯一请求构造函数，增加可选真实 tool_observations；旧读取调用没有这个字段时仍保留原输入结构。强模型只能诊断，不能提供工具参数、补丁或替换最终回答；RWKV 自己选择操作。没有恢复 Coordinator、固定角色流水线或新训练。

红绿证据：终止字段缺失、旧共享入口不支持准备父 State、建议构造不接收工具观察，分别先失败。最终针对性 36 passed；完整 tests/ 为 1603 passed、零跳过，包含原 Torch/State/浏览器回归。测试开发中曾把 Controller transition 限制误写为 generation 限制，已按真实边界拆开断言；一次针对性测试与临时红测源码重叠，结果标 INVALID 后重跑。原始失败记录保留，不宣称全程首次通过。

## 冻结与执行

复用上轮 r2 原失败工作区和原 State，不引入新任务/数据集版本。REGISTRATION 与正式 CONTRACT 在任何新作答前冻结目标、外部行为测试、事实忠实性要求、State、源码、采样、每遍 12 调用/12 transition/600 秒、普通 1800 输出 token、旧特殊 Final 1400 上限，以及继承的失败和观察计数。次序 independent-r1、advised-r1、advised-r2、independent-r2。

先用生产追加函数把父末尾尚未注入的第五次真实目录错误追加一次，得到共同 child State；没有新生成。四个分支使用完全相同的 Goal 与该 checkpoint：无建议首次生成直接接该点，建议组只额外追加同一份建议事件。强模型只收到父阶段可见的原读写内容、真实观察和原目标；不见外部测试结果、正控实现或隐藏评分。未替模型选择参数、修代码或强制工具顺序。

原四次启动遇到本地 29613 端口断开：宿主也连接拒绝，非私有挂载引起。远端服务仍 active，恢复本地 SSH 转发，不部署或改远端源码、不使用远端 Git。恢复后服务声明的 build/tokenizer/State 格式与共同父 State 一致；原生导入与后续 lineage 核验通过。这不是新做服务器逐文件部署核验。四条原始无效记录留在 runs/；同条件重跑在 retry_runs/，原建议不重生成。基础设施恢复补充清单写入晚于首个重跑启动：首稿误读嵌套能力字段，后续一致性核验通过；原任务/源码/评分/预算冻结未变。

四次新命令都是 FileNotFoundError、exit_code=null；外部冻结验证均失败，不计为模型亲自执行。没有 final_answer，所以不能标作虚假声称完成。advised-r2 的实际修改与无交付分开记录，但没有功能收益。

**已确认的工程行为：**失败计数为 5 的父任务被续接后，重犯一次旧错立即达到 6 并中断。这个条件已经预先登记并原样保留，因而对照有效；但没有为模型提供完整 12 次新生成机会。资源计数跨续修继承与模型自己重复错误是不同问题，不应把前者造成的提前结束全归到模型能力。

**已观察的模型行为：**真实错误和建议进入输入后仍选相同 cwd；一次漏必需参数，一次无效改写，没有接入实际 CLI。不能归因为读不到文件或已证实的 State 丢失，也不能用有限重犯次数推断更大预算下必然失败。

**强模型自身的问题：**它正确指出 CLI 缺失和测试未启动，却称 fetchmany(limit or None) 符合 Python 层需求，漏掉默认 None 错误；还优先批评空摘要并引入未要求的类型边界。系统提示仍包含摘要语境，这与未完成的编程续修阶段不够贴合；是否造成漏诊还需对照，不能全部归因于提示词。建议原样保留，未挑选、纠正或直接转成训练数据。

**输入/State：**六次真实输入完整重建，工具错误与只一次建议追加核验通过，声明 native 父 digest/Profile/模型 SHA 一致。每个首次输入与共同 checkpoint 的关系已明确核对；未做新的张量等价实验。完整逻辑输入为 16995–18599 token，包含累计历史；native State 使用增量追加，不等同一次 prefill 长度或服务配置名中的 ctx16384。输入负担可能影响能力仍是假设，本轮不证明截断或长上下文能力上限。
