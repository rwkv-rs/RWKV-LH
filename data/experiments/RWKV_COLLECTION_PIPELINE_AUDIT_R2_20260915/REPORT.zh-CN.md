## 从实际调用链确认的未完成项

1. **纠正证据缺口（高优先）**：新入口 → agent_batch → run_coding_job 默认 session_factory，不启用 correction_snapshots.generation_snapshot_audit。旧 run_ultradata_collection_r3 与 run_r6_evaluation 显式启用。当前 validate_generation_snapshot 要求每个 request 的 before、SNAPSHOT.json 和紧邻 generation_started 的事件。已有工具前后快照及普通日志可能支持其他重建途径，但新入口没有实现并验证等价重建，不能保证未来编码纠正准入。不能据此断言普通输入/State trace 都缺失。
2. **批次结果持久化与调度**：run_agent_jobs 等整批返回，新入口再逐条 finish；快任务结果不会及时写入队列，慢任务形成批次屏障，进程池每批重建。应持续有界调度、逐条落盘、保存 attempt，故障时以真实结果/收据对账。不能把尚未收集进队列的结果说成实际 trace 丢失。
3. **容量与 State 回收**：只在批次开始检查 queue 所在卷。没有远端 State 卷、输出卷、NAS 各自水位及增长率，也没有从本采集器调用任务级 Native release。服务存在回收 API，不等于本管线已接通。不能启用粗暴定期删除 blobs。需要成功与失败任务分别确定保留边界，核验归档后按引用生命周期释放。
4. **全局时间/资源预算和故障回压**：仅单题 max_calls/max_seconds，没有 36 小时全局截止、总生成/token/磁盘预算、连续服务错误停发。预算到点时必须排空/记录在途任务，不能计为成功；不能在服务持续失败时把全部题目刷成 recorded。
5. **并发尚未证明**：native_state_service 的 journal.execute(...execution_lock=self.request_lock) 覆盖 invoke；journal._run 在锁内 await 全部调用。服务还使用共享 _active_request_id。增大客户端并发不能解除这个生成串行段；直接删除锁有请求身份串扰风险。保留锁，先做服务实际并发/State 隔离探针，再决定根因修复。未测量最大稳定并发或吞吐。
6. **运行冻结不完整**：runtime.json 仅保存 RuntimeSettings，未绑定采集器源码、完整工程/engine manifest、整个任务清单、验收器实现和总体预算；并发不在快照中。生产服务自身有 attestation 能力，但本轮采集登记尚未与之绑定。文档列出开跑门不等于 CLI 强制门已实现。
7. **外部验收未接通**：acceptance_path 只做 SHA 核验；新入口并不执行或持久化独立验收。本轮可以跑后归因，但验收规则与可运行验证器必须事前固定，否则一天半后可能剩下大量无法判断的回答。
8. **来源复建尚未完成**：54 个已审计 SFT 来源不等于 54 个可执行任务。Code 原仓库版本、General 初始材料、Search 工具服务需要逐项证明；不得从最终答案反造初始环境，也不能以静态审计数量计入 3 万运行。

## 开跑门与处理顺序

先处理 Q1–Q6 的队列/私有材料隔离问题，补先失败后通过回归；同时接通生成边界纠正证据和任务收据。随后绑定冻结清单、外部验收、State 生命周期和各存储卷水位，再做持续调度和并发探针。Q7 与 SFT 复建在来源侧解决，不能用重复采样凑独立题。

验收至少包括：任务前校验失败、完成一个后中断另一个、杀掉队列/worker、服务不可用、磁盘低水位、重启重复领取、运行参数/源码变化、跨任务参考泄露。每个场景必须对上任务、attempt、真实模型请求及保留证据。

通过这些工程故障注入后，再进行有真实 SFT/项目任务的有界持续试跑；测得任务吞吐、失败回压和 State/磁盘增长稳定后才能登记 36 小时正式运行。没有固定任务冻结与实测吞吐，不能承诺一天半跑完 3 万题。

当前裁决 NO-GO；不启动长跑。本轮只审计与留证，问题未修复，不恢复训练、强模型纠正或大规模架构重构。
