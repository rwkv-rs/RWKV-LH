# Round131 — Final-Operation Confidence Deferral — PROTOCOL (preregistered)

**Status:** preregistered 2026-08-21, after the label-blind calibration and before implementation or
R131 execution. This is the third and last single-variable screen feeding the already-locked R132
terminal round. Baseline is the repaired canonical R126 v19-P1 path: order ensemble default-off,
one canonical RWKV generation per decision.

## 1. Single variable

For a syntactically valid **normal action-lane** `final_answer`, read the token logprobs returned by
that same canonical RWKV generation and compute:

`final_operation_confidence = mean(token_logprob for generated tokens overlapping "final_answer")`

If the metric is strictly below the frozen threshold
`-0.40040510160761184` and the run has not deferred before:

1. rollback that candidate without executing an action or delivering its text;
2. persist the rejected raw candidate, exact metric, token count, threshold, and decision id;
3. append one objective `terminal_confidence_deferred` event to the **same** RWKV action lane;
4. continue the lane for one ordinary direct-operation decision.

The event states only that the previous explicit Final was deferred by the locked operation-token
confidence rule and instructs the model to choose one displayed direct operation, or a new Final when
ready. It contains no task-specific text, acceptance data, guessed field, reviewer conclusion, or
controller-authored business answer.

### Frozen boundaries

- At most **one** deferral per run. Usage is derived from the persisted causal ledger/rejected
  decision, so restart cannot grant a second deferral.
- Forced `terminal_answer` after transition/protocol/failure exhaustion is **never deferred**. At
  that point there is no remaining action budget to which a confidence rule can defer.
- Missing/malformed logprob metadata is an audited no-op (accept canonical behavior); the offline
  gate and Full90 audit require metadata availability on every eligible Final.
- Non-final operations are never scored or changed.
- No K=3, no alternate ordering, no reviewer, no synthesized action, no comparison of answer text,
  no task parsing, and no hidden acceptance at runtime.
- Sampling and generated bytes are unchanged by the OpenAI-compatible `logprobs=1` response option;
  it adds response metadata only.

This is one terminal-decision variable. It can cause one additional causal continuation, but it is
not a second judge or a replay of the same prompt: the low-confidence candidate is rejected by a
fixed numeric rule and the persistent RWKV lane advances through a visible objective event.

## 2. Calibration and frozen threshold

The complete population rule and source hash are recorded in
`R131_CONFIDENCE_CALIBRATION_20260821.md`. The p10 threshold was selected across 63 measurable normal
Final replays without reading category labels. Post-selection, the below-threshold set contained
five prior FP and two prior TP. That mix is not used to tune the threshold.

No post-run change to the metric, span mapping, inequality, threshold, one-deferral cap, or eligible
lane is permitted.

## 3. Hypothesis and attribution

The final operation token is the model's own same-generation boundary choice. A low logprob on that
literal is a falsifiable signal that `final_answer` is positionally weak relative to another
continuation. Deferring only the bottom decile once may let the same RWKV state take the missing read,
write, or verification action and convert premature completed-wrong cases from FP to TP.

Predicted help slice from the frozen calibration: M06, H08, M15, M23, M26. Predicted regression
canaries: B08, M11. These labels are for post-run causal checking only; runtime uses no case id.

An attributable FP→TP requires all of:

- the case was FP in the source-frozen repaired canonical calibration run;
- the R131 audit contains a below-threshold `terminal_confidence_deferred` decision;
- at least one later direct action is executed before the accepted Final;
- external acceptance becomes TP.

A score flip without a deferral event is variance, not mechanism evidence. FP→OTHER, TP→OTHER, or a
second Final immediately after the event with no intervening action is not helpful firing.

## 4. KEEP / REVERT and R132 eligibility

Frozen baseline references: R126 official {Strict 36, FP 30, FN 0, OTHER 24}, confirmatory
{Strict 34, FP 31, FN 0}; single-run Strict variance ±3.

- **G1:** byte-precision 5/5 (B01, B06, B13, B19, B28).
- **G2:** Strict ≥ 34 (confirmed floor).
- **G3:** FP ≤ 30, FN ≤ 1, OTHER ≤ 24.
- **G4:** 90/90 valid Finals, zero running.
- **G5:** lose no more than two cases from the reconstructed R126 official TP set (≥34/36 retained);
  also report retention on the locally available R128 TP proxy set (≥29/31 is the same ≤2-loss
  guard). This operationalizes the locked R132 32/34 retention intent despite the R126 confirmatory
  per-case artifact not being present locally.
- **G6:** confidence metadata present for every eligible normal Final; at most one deferral per run;
  zero deferrals on forced terminal-boundary Finals.

**KEEP / R132-ELIGIBLE** iff all G1–G6 pass, FP < 30 at Strict ≥34 (or Strict ≥37 with FP≤30), and
there is at least one attributable FP→TP as defined in §3. Otherwise **REVERT** to the repaired
canonical default and mark confidence deferral EXCLUDED in the R132 ledger.

The raw aggregate score alone is insufficient. If the rule never fires helpfully, or the score is
inside normal variance without an attributable flip, it is a no-op and must be excluded.
