## 真实输入、State 与训练候选

76 个已写任务全部通过生产 `replay_run` 重建：原始 tokenizer 输入、bootstrap、观察追加和 State 父子摘要关系一致；完整题面在对应原调用中可见。没有重新生成“看起来一样”的提示词。

其中 30 个任务已人工复核公开题意、算法与唯一输出约定，再调用生产 `validate_stdio_correction` 在服务器完成原边界绑定、失败 baseline、真实 Harness 写入和隔离私有验收。原始 30 份证明共 306766 输入 token、6485 目标 token。审核者是当前 Codex，同时也是作者；没有冒充第二个独立模型审核。

这些是验证候选，不是已冻结训练行：仍需逐任务去重/近似污染排除、原来源与固定回归隔离、训练器格式及上下文上限核验。原始 30 份中有一条总序列 28679 token，超过既有 24576 训练窗口；不能截断。该素数计数来源另有全文已可见的首次错误写入边界（5390 输入 token），已改用这一真实早期边界重新验证并通过，保留后期长输入证明，不把一个任务算成两条独立来源。见 `EARLY_BOUNDARY_SELECTION.json`。选择后仍为30个独立来源，输入合计283630 token、目标6485 token、最长24213 token，全部容纳于既有24576窗口，无截断；尚未完成冻结隔离门。

## 已复现并修复的候选缺陷

- 倒序数组：整数转换破坏输入数字的原始表示，修复为保留原词元；44/53 → 53/53。
- 乒乓球策略：第一版推导错误；独立小状态推演后修改，5/42 → 42/42。
- 阈值子数组：未处理下限大于上限的空区间，出现负数。独立 1500 查询穷举中旧版 49/50 组失败、新版 50/50 组通过；固定验收 28/35 → 35/35。
- 第 k 小约数：原 O(sqrt(n)) Python 枚举在当前三秒限制下超时；Codex 首版 Pollard 批量 gcd 又漏掉中间因子、在小合数上循环，独立 323、289、437、899 等复现。逐步 gcd 新版通过 31/31，失败候选保留。

素数早期边界审核还出现两次人工误归因（协议拼写、转义文本）。生产 parser 与 compile 检查均证实原命令合法且可编译，两个错审被排除保留。最终只保留复杂度依据：公开上限1e8下原实现三秒超时，奇数筛候选本地约0.31秒完成；固定私有验收另已通过。不将本地运行时间与服务器时间混成性能提升比。

生产 `rwkv_lh/` 和用户已有五处修改均未被本轮更改。完整工程回归 1894 passed、0 skipped（341.78 秒），代码身份与该次回归一致。算法候选另经各自冻结私有用例和上述独立检查，不用工程单元测试替代题目验收。

## 源数据与验收问题

`SPECIFICATION_REVIEW.json` 单独记录：缺公式、缺图片、缺输入输出规格、交互题、任意合法输出、表述歧义。不能把这些全归因于 RWKV，更不能让纠正模型照抄某一参考答案。哈希构造的独立语义检查同时拒绝重复、非法字符、错误哈希、错误行数和空串五类负例；旧 exact 结果不重算。

已读并编写的这批只证明相应固定产物正确，不能自动证明最坏复杂度、通用自主交付或多文件维护能力。

另外修复了两处本轮证据工程问题：临时状态汇总按独立任务计数，并只用真实最终文件复验计算原产物通过，避免重试/快照重复计数；Git 原有 `text=auto` 会转换92份题面的CRLF，实验目录增加仅针对 TASK.md 的 `-text`，暂存对象与1024份源题面字节核验由92处不一致到0。两项都有独立红→绿记录，不改变私有评分。

生产目标仍是 RWKV 自己的 Code Agent 与专属 Harness；成本、延迟、吞吐是在相同交付质量下衡量的属性。本轮未恢复六角色流水线，未新增模型接管架构。
