# Round44 Preregistered Protocol: One Auditable Observation View

## Frozen diagnosis

Round41 Basic30 is the retained code baseline: Strict `17/30`, External `24/30`, FP `3`, FN `7`, model requests `467`. Round42 and Round43 semantic second-pass experiments were rejected and fully reverted.

The next defect is an internal evidence-presentation split, not a wire-format defect:

- Task-local memory rendering already projects a post-action snapshot into observed fields.
- Goal provenance rendering serializes the raw internal memory envelope, truncates it at 240 characters, and labels it `content_preview`.
- The same authoritative memory therefore has two different model-visible shapes. Snapshot JSON metadata consumes the preview budget, while action-result output is mixed with `ACTION RESULT METADATA`.
- In `E2E-B04` and `E2E-B29`, the selected actual snapshot contains incorrect copied content. The bytes exist in state, but Goal receives them inside a second JSON string envelope. In `B29`, the model selected the correct independent actual/source pair yet asserted equality between visibly unequal values.

## Single registered change

Introduce one deterministic `rwkv-lh.observation-view.v1` projection for persisted `MemoryEntry` observations and use it in both task memory rendering and Goal provenance catalogs. The projection preserves displayed data byte-for-character and explicitly reports any model-view truncation; the persisted record remains the complete authority.

The view may only expose fields already present in the authoritative memory/artifact records:

- memory ID, memory kind, producer task ID;
- observed data copied byte-for-character from the registered action-result output or snapshot `content` field;
- registered observation metadata such as completeness, truncation, path, media type, size and hash;
- referenced artifact path/hash/media type;
- explicit view truncation metadata when the model-facing view is bounded.

For a registered action-result record, split the stored `ACTION RESULT METADATA` suffix only when it parses as a JSON object. For a registered `rwkv-lh.post-action-workspace-snapshot.v1` record, expose its existing `content` and metadata fields. Unknown or malformed records remain opaque data; no field is invented or interpreted semantically.

Goal provenance catalog schema advances to `rwkv-lh.goal-criterion-provenance-catalog.v2` and embeds this observation view. The immutable Goal is represented with the same explicit data/completeness shape. Reference eligibility, source roles, ownership, lineage, Goal criteria, actions, and RWKV decisions are unchanged.

## Explicit boundaries

- This is not the protocol format converter. `tool_protocol.py` remains limited to lossless mapping of registered common RWKV wire forms into one canonical call shape.
- The observation view does not compare actual and expected values, select references, determine relevance, generate expected values, add criteria, accept tasks, or alter RWKV output.
- The authoritative `MemoryEntry.content`, artifact hashes, and raw/normalized protocol audit records remain unchanged.
- No external acceptance result or benchmark answer is available to the Controller or model.
- No case-specific text, path, value, criterion, or tool rule may be added.

## Fixed validation

Before online execution:

1. Full offline pytest.
2. LH-Control-30: `30/30`.
3. RWKV-E2E-90 catalog validation: `90/90`.
4. Unit coverage for action-result projection, snapshot projection, malformed/unknown opaque fallback, view truncation, raw-state preservation, and use of the same view in task and Goal surfaces.

Fixed online canary, in this order:

`E2E-B04`, `B27`, `B29`, `B05`, `B06`, `B08`, `B11`, `B12`, `B13`, `B18`.

The first three are the Round41 false positives. The remaining seven are externally correct Round41 controls recovered by canonical evidence roles.

Run Basic30 only if the canary has at most one false positive and at least six of seven correct controls remain Strict. Retain/upload eligibility requires all of:

- Basic30 Strict greater than `17/30`;
- Basic30 false positives at most `1`;
- no increase in false negatives above `7`;
- offline, LH-Control, E2E catalog, boundary, exception, and historical regression tests pass;
- raw RWKV final output remains byte-identical and no semantic field is generated by the projection.

Similarity/evaluation code, data, sampling, thresholds, and case ordering are frozen before the first online call and will not be changed after results.
